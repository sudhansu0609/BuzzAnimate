## G — gestures chosen per line

**Where:** `crates/buzz-act/src/perform.rs` (new one-shot `Action`s),
`crates/buzz-app/src/episode.rs` (`perform_actor`, `SegKind`).

Today a Cast actor in an episode only walks, talks and idles; the director
(`buzz_act::direct`) already maps verbs to one-shots (`Sit Stand Turn Point
Reach React`) but the episode builder never uses them.

1. **New one-shots** in `perform::Action`: `Wave`, `Nod`, `HeadShake`, `Shrug`,
   `Namaste` (palms together at the chest, small bow). Same contract as the
   existing one-shots (`loops() == false`, arrive → hold → return, `pose_at`
   shapes, an entry in `label/undo_label/description/cycle_seconds`). They must
   work on the Cast rigs (auto-rigged, DWPose bone names) as well as the
   standard puppet — find how `Point` resolves arm bones and reuse it; a rig
   without a head bone skips Nod/HeadShake with a report note, not an error.
2. **Choosing a gesture** — a pure function `gesture_for(line, action_text) ->
   Option<(Action, f64 /*amount*/)>`, deterministic, unit-tested:
   - From the **action line** that precedes or follows the dialogue and names
     the speaker (English verbs, reuse `direct`'s stems: point/gesture/indicate
     → Point; wave/beckon → Wave; reach/grab/take…up → Reach; flinch/gasp/jump
     → React; sit → Sit; stand/get up → Stand; nod → Nod; shrug → Shrug;
     bangs/slams/thumps → React at amount 0.6).
   - From the **dialogue itself** (Romanised Hindi + English): leading
     `haan|ha|ji|theek|accha` → Nod; leading `nahi|nahin|na|no` → HeadShake;
     `namaste|namaskar|pranam|ram ram` → Namaste; `arre|oye|suno|hey` at the
     start → Wave (small, 0.6); a line ending `?` with no other cue → Shrug at
     0.5; ALL-CAPS or `!` → the talk gets amount 1.3 (bigger), no extra gesture.
   - At most **one gesture per line**, and none on two consecutive lines of the
     same speaker unless the action line asked for it (it reads as fidgeting).
3. **Placing it:** the talk segment is split: talk → gesture (one-shot,
   `0.9 s`–`1.4 s` by action, starting `0.15 s` after the line starts) → talk.
   A gesture longer than the line is clipped to the line. Sit/Stand change the
   body state for the rest of the scene the way `direct` handles them.
4. **casting.json override:** per character `"gestures": false` turns it off;
   per scene `"gestures": false` likewise. Default on.
5. **Report:** `SceneReport` lists each gesture (`speaker`, `frame`, `action`,
   `why` = the word that chose it) so the morning README can show it.

## P — parallel scene renders

`export_service.rs` runs exports **one at a time on purpose** (its header: each
export builds a second wgpu device; parallel would quadruple VRAM and fight
NVENC). That reasoning is untested on this machine (RTX 5060 Ti 16 GB, driver
617 — 8 NVENC sessions; 28 threads). If an export is CPU-bound (scene
evaluation, readback, ffmpeg pipe) running 2–3 at once wins; if it is
GPU-bound it does not.

- **P0 (planner, measure first):** one Ep1 scene, 3 runs each: alone; 2 at
  once; 3 at once (separate processes via the headless `--render`). Record
  wall time, GPU utilisation, VRAM peak. Gate: build P only if 2-at-once
  finishes two scenes in ≤ 70 % of the serial time.
- **P — how (planner, 2026-10-11, after P0):**
  - `export_service::ExportQueue`: `active: Option<Active>` → `Vec<Active>`;
    field `max_parallel: usize` (set by `App` each pump, ≥ 1).

    `is_idle`, `outstanding` count all of them; `active_task` → `active_tasks`
    (or removed if unused). Existing tests keep passing with a cap of 1.

    new `buzz_ui::Workspace` field, `#[serde(default = …)]` **4** (P0 knee:
    34 % of serial at 4; 6 is 27 % but needs 12.6 GB VRAM, leaving none for
    the editor or the user's local AI). `vram_cap`: sampled once when the
    queue goes from idle to busy — `nvidia-smi --query-gpu=memory.free

## BG — generated background → layered vector asset

**Where:** new `crates/buzz-app/src/backdrop.rs` (ComfyUI client + split +
trace), dialog `Insert ▸ Generate Background…`, agent tool, episode casting.

1. **Generate:** POST a Z-Image workflow to ComfyUI (`/prompt`, poll
   `/history/{id}`, fetch `/view`). Discover ComfyUI at `COMFYUI_URL` env, else
   `127.0.0.1:8188` → `+20` probing `/system_stats`. Workflow: read
   `<estate>/BuzzEdit/workflows/zimage1.json` + the `image` role bindings in
   `manifest.json` (prompt, seed, width/height) — do not copy the JSON into
   this repo; fail with a clear message if missing. Prompt = user text +
   style suffix "flat 2D cartoon background, clean shapes, bold flat colours,
   no people, no text, no characters". Size 1344×768 (16:9), seed from the
   dialog (deterministic). Requests carry no `Origin`; only 127.0.0.1/localhost
   URLs are accepted.
2. **Split into depth layers** (no depth model exists): `Sky` = the region
   connected to the top edge whose colour stays within tolerance of the top
   rows' palette (flood fill in Lab, tolerance 18); `Ground` = everything
   below the horizon — the horizon is the lowest row where Sky still touches
   ≥ 30 % of the width, or the VLM's `ground_y` when `buzz_ai::llm` is up;
   `Far`/`Mid` = the rest split by connected components: components whose
   bottom is above the horizon + 3 % → Far, others → Mid. Each layer is an
   RGBA plate with transparent elsewhere; hidden pixels behind Mid are filled
   from the nearest Far/Sky colour so parallax shows no holes.
3. **Trace** each plate with `buzz_scene::trace` (colours mode, colours 24,
   speckle 8; per-layer options in the dialog), onto layers `Sky`, `Far`,
   `Mid`, `Ground` with depths so the camera parallaxes them.
4. **File** the result as an asset in `Backgrounds/` (`AssetLibrary::save`),
   name from the dialog. The PNG is kept beside it for reference.
5. **Episode:** casting scene `"generate_background": "<prompt>"` generates
   once (cached by prompt+seed in `<out>/backgrounds/`) and uses it as the
   scene's `background`.
