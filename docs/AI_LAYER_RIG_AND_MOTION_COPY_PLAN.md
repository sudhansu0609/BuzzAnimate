# AI Layer Rig + Motion Copy plan (2026-10-21)

User ask, 2026-10-21:
1. "The AI should understand the body parts, then rename them, put them on
   different layers and rig the layers via layer parenting."
2. "One character can copy the movement of another character, the same with
   objects, rigs etc."

## What exists (survey 2026-10-21)

* **AI ▸ Auto-Rig Vector Character** (`App::ai_rig_vector_character_async`,
  `app.rs` ~9502; `rig_vector_character_from_detected_skeleton`, ~2840;
  `buzz_ai::rerig::rerig_vector_character`):
  1. Renders the symbol and runs DWPose.
  2. Builds 11 biped capsules.
  3. Maps parts to slots, using overlap plus a name affinity, and tries the
     L/R swap.
  4. Outputs a **bone** rig (`Armature` object).

  Its limits:
  * Parts come from `rig_parts_for_symbol` (`app.rs` ~2719). There is **one
    part per symbol layer**: several objects on a layer are grouped together,
    and nested instances are opaque.
  * It renames nothing and creates no layers.
* **Layer rig builder** `rigging::place_layer_rig` (`rigging.rs` ~707). It is
  private, takes `LayerPart{slot, name, artwork, joint}` plus `parents`, and
  makes one layer per part, keeping paint order, with `set_follows` links
  (front-most leads; fixed 2026-10-21). It only works on **stage** layers;
  callers are `rig_character_layers` (stage objects, joints from
  `autorig::fit_slots`) and `bones_to_layers`. Layers are named after slots:
  Hips, Chest, Head, Shoulder L/R, Elbow L/R, Thigh L/R, Knee L/R, and
  `biped_full` adds Wrist L/R, Ankle L/R and Brow L/R. `buzz_act::layer_rig::rig_of_layer`
  recognises a rig by these names.
* **`rigging::repair_layer_rigs`** rewires links and rebakes keys so poses are
  unchanged. It already works inside symbols.
* **Splitting a merged drawing**: only the image tracer does it, from raster
  ownership masks (`character.rs` ~4254). There is no vector cut by skeleton.
* **Motion copy**:
  * `Editor::retarget_performance` (`editor.rs` ~9221) only works for **bone
    rigs**, needs equal bone counts, and does no scaling.
  * There is no Copy/Paste Motion, no Copy/Paste Pose, and no key copy between
    layers or instances.
  * CopyFrames/PasteFrames only paste onto the same layers.
  * Reusable pieces: `buzz_act::layer_rig::{rig_of, CharacterRig,
    rest_armature, placement, set_placement, key_at}` (one view of both rig
    kinds).

## Part R: AI Rig as Layers

**Behaviour.** Select a character instance (or a Library symbol) and choose
**AI ▸ Rig Character as Layers…**.
1. It finds the skeleton: DWPose when installed, otherwise `autorig::fit_slots`
   from the bounds and names, marked "lower confidence".
2. It identifies **every piece**. A piece is each top-level object on each
   layer of the symbol at the chosen frame. A layer holding an arm and a sleeve
   gives two pieces.
3. It assigns each piece a slot from `biped_full`. Pieces that match no limb,
   such as eyes, mouth, hair or props, go to the slot they overlap most. Head
   pieces always go to Head.
4. It renames the pieces:
   * Layer names: the lead piece's layer becomes `<Slot>` (e.g. "Elbow R"), and
     extra pieces become `<Slot> · <old name or role>` (e.g. "Head · eye").
   * Nested symbols with generic names ("part 14", "Symbol 3", "copy N") are
     renamed `<Character> <Slot>`, kept unique.
5. It puts each piece on its own layer **inside the character symbol**. That
   keeps it one symbol, so Swap, Library and casting still work. Paint order
   stays exactly as drawn, so the picture doesn't change.
6. It rigs with layer parenting through `place_layer_rig`, generalised to any
   layer stack (stage or symbol), with pivots at the joints.
7. **Existing animation is kept.** Every keyframe of the original layers is
   carried onto the new layers by object id. The keys are then rebaked by the
   `repair_layer_rigs` rebake, so every frame looks the same (≤ 0.5 px).
8. It shows a review: a part → slot table you can correct, plus a sheet of the
   standard poses. Then Apply, as **one undo step**.
9. Agent command `ai_rig_layers {symbol|element, frame?, split_merged?}`.

**Merged drawings (R4, last).** When one drawing holds the whole body, the
fills and strokes have to be cut along the skeleton:
* Each path region is assigned to its nearest bone capsule.
* Shapes spanning a joint are cut with boolean intersection against
  per-bone regions (Voronoi around bone segments).
* Each cut part gets a joint overlap disc, so bending shows no gap (the same
  idea as Extend Part).

This step is optional in the dialog and off when the pieces are already
separate.

## Part C: Copy movement between characters, objects and rigs

**C1 Copy Motion / Paste Motion** (Animate-style, for any object or instance)
* Select the frame span on a layer (or an object at the playhead), then
  **Edit ▸ Timeline ▸ Copy Motion**. This stores a `MotionClip`:
  * per keyframe: transform, pivot, colour effect, alpha, and for instances
    first frame/loop;
  * the tween and ease settings;
  * the frame offsets.
* Select one or more target objects or layers, then **Paste Motion** at the
  playhead. Pasting:
  * writes keyframes at the same relative frames with the same tweens, never a
    per-frame bake unless the source was baked;
  * is **relative** by default, so the motion is applied as a delta from the
    clip's first key and the target keeps its own starting place;
  * has an "absolute" option.
* **Paste Motion Special…** chooses which parts to paste: position, scale,
  rotation/skew, colour, timing. It also offers a time stretch (×0.5–×2) and
  "fit to selected span".
* One undo step. Works on the stage and inside symbols.

**C2 Copy Pose / Paste Pose** (rigs, one frame)
* Works between bone rigs and layer rigs, in any combination, through
  `CharacterRig`. Slots are matched by name.
* It copies **joint angles**, not positions, so a short character takes a tall
  one's pose correctly.
* A slot missing on the target is skipped, and the status line lists what was
  skipped.
* It keys at the playhead (auto-keyframe).

**C3 Copy Performance** (whole movement, rig to rig): generalise
`retarget_performance`.
* It accepts layer rigs and bone rigs in any combination, mapping slots by
  name, so equal bone counts are no longer needed.
* It copies a frame range with an offset, and a time stretch.
* Root motion (the Hips / instance travel) is scaled by the hip-height ratio,
  so a smaller character takes smaller steps.
* The keys land on the target's layers, or on its armature.
* The stage instance's own travel is copied with C1 in the same step, so "make
  Munna walk like Lalten" is one command.

stretch?}`, `copy_pose`, `paste_pose`, `copy_performance {from, to, range?,
